# UPSC CSE 2027 — Complete Preparation Guide

Complete preparation guide for the UPSC Civil Services Examination 2027, written for a complete beginner with no prior UPSC preparation, coaching, or subject background. Covers every paper of both Prelims and Mains, with the Mathematics optional (Papers VI and VII) included as the selected optional subject.

## Conventions

Each paper folder contains:

- `<paper-name>-Syllabus.md` — the official UPSC syllabus, verbatim
- `<paper-name>-Curriculum.md` — a comprehensive, phased curriculum, generated from the researched exam pattern, the syllabus, and PYQs; doubles as the index
- `<paper-name>-PYQS/<year>-<paper-name>.md` — year-wise PYQ notes (2013–2026), one file per exam year; for two-paper subjects, both papers appear in separate Paper I and Paper II sections
- `<chapter>.md` or `<chapter>-part-N.md` — chapter content; split parts only when a curriculum chapter is too large, with every part linked from the curriculum
- `Prelims-<paper>-TESTS/<test-id>.md` — historical repository practice tests and feedback
- [Prelims GS-I full-test](Prelims-General-Studies-I/full-test/) — historical full-length GS-I practice artifacts
- `Mains-<paper>-TESTS/<test-id>.md` — legacy repository assessment-file convention

Website assessments, feedback, learner progress, revision tasks and private reading data are created dynamically in application storage; learning material alone is sourced from Git Markdown. [Reading tools](SPECIFICATION.md#reading-tools) include private notes, highlights, bookmarks and saved reading position.

## Web application development

Requires Node.js 24 and npm. Run `npm ci`, `npm run content:build`, and `npm run dev`. Run `npm run check` and `npm run build` before opening a feature PR. The build derives the public learning catalogue from curriculum chapter links; historical tests, keys, PYQs and method documents are excluded. Runtime configuration will be documented in `.env.example` as private features are added.

Release features through separate branches and PRs; merge with a merge commit, without squash. The public reader is deployed at [cse27.vercel.app](https://cse27.vercel.app/). Owner authentication is the next release; private reading persistence and assessments remain pending.

### Owner authentication setup

Production configuration uses `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`, server-only `OWNER_EMAIL`, and `APP_URL`. Leave production credentials out of preview/development environments. Authentication fails closed when configuration is absent; public learning routes stay available.

In Supabase Auth URL Configuration, set Site URL to `https://cse27.vercel.app` and allow `https://cse27.vercel.app/auth/callback` and `https://cse27.vercel.app/auth/callback?next=/auth/recovery`. Email confirmation and recovery need a working email provider. For Google login, configure a Google Web OAuth client with the Supabase project's `/auth/v1/callback` redirect and enable it in Supabase Auth Providers.

The verified owner must create/confirm the account or sign in with Google. Provider configuration and a real owner login must be verified before private study-data features are enabled. Application routes enforce the owner allowlist; provider-level sign-up restrictions remain a separate Supabase configuration step. Do not put the owner's identity or credentials into Git.

### Bookmark recovery

In **Bookmarks → Download encrypted backup**, enter a passphrase of at least 16 characters and keep it separately from the downloaded file. This export includes bookmarks, saved reading positions, notes and highlights when enabled. It fails if Supabase cannot return the full snapshot.

To restore, apply the private reader migrations to a recovery database and provision its verified owner in `reader_private.owners`. Use the recovery owner's UUID in the command below. Supply a PostgreSQL connection through your local PostgreSQL client configuration and keep the passphrase out of shell history.

```bash
set -o pipefail
read -rs -p 'Backup passphrase: ' bookmark_passphrase
printf '%s' "$bookmark_passphrase" | node scripts/restore-bookmarks.mjs cse27-bookmarks.enc RECOVERY_OWNER_UUID | psql -X -v ON_ERROR_STOP=1
unset bookmark_passphrase
```

Use an empty recovery database for the rehearsal. The restore runs in a transaction and aborts on duplicate bookmark IDs. Verify the owner can open the original bookmark locations after restore.
